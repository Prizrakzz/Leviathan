# `sql/athena/migrations/silver/` — applied catalog-migration manifests (SILVER-F012)

Every APPLIED change made by `leviathan.silver.migrate.CatalogMigrator.apply_table` writes one
manifest here, named `<UTC-timestamp>_<table>_<change_type>.json`. Each manifest records:

- `plan` — the frozen `MigrationPlan` (desired/live hashes, diffs, the exact `create_table` /
  `update_table` call, the registered-partition SD audit, and any refused unsafe diffs);
- `backup` — the live `TableInput` + its catalog hash captured immediately BEFORE the mutation
  (the executable-restore basis; see `CatalogMigrator.restore_table`);
- `guard_mode` + `fencing_token` — the publish-guard mode the change ran under and the lease
  fencing token held at mutation time.

This directory is intentionally empty on `p65-impl` (R1): apply is a guarded, post-approval action.
R1 produces only the READ-ONLY dry-run plan artifact at
`reports/silver_readiness/<baseline>/F012_migration_plan.{json,md}` (generated by
`scripts/silver/plan_catalog_migration.py`), which across all 43 tables reports **0 unsafe** diffs.
